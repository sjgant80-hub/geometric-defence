A node that reads handwritten digits guards its door twice. First, a signature check on the raw bytes, before anything is read. What this is

This is Rung 5 of a ladder of tests toward computing by geometry (small networks that read by settling into stored patterns, with no trained model) instead of by large models. A signature proves who sent something, not that it is safe: a stolen key signs attacks perfectly. Rung 5 asks whether the shape of the computation itself can be a second wall. If the settle finds nothing an input fits, the node turns it away, and antibodies learned on one node can be shared to others. What the other rungs found, held and failed, is on the ladder page.

Words on this page

FloorThe first wall: the sender's key is on the roster and the Ed25519 signature holds on the raw bytes, checked before anything is parsed. The keys here are derived from public seeds so anyone can re-run the record; a real deployment generates a secret key on each sender.
Settle, fitThe node flips the input's bits one at a time towards its stored digit patterns until nothing more changes. The fit is how strongly the settled state matches them.
Non-fit, θAn input whose fit is below θ is rejected as fitting nothing the node knows. θ came out at zero on the tune digits, so, by the disclosed amendment, zero fit is what counts as non-fit.
AntibodyA stored pattern of a known attack. An input is rejected if the antibodies match its settled state at least as well as the node's own patterns do.
Scrambled, noise, invertedBlind attacks, all validly signed: a real digit with its pixels shuffled; random values; a real digit with its ink turned inside out. Noise and inverted are the "crude" attacks on this page: nothing like a real input.
MimicAn attacker who can query the defence: it starts from noise and, for 300 queries, keeps any one-pixel change that raises the node's fit.
Harmful shareAn antibody set grown from real digits, validly signed: it was expected to be refused because it would reject real inputs. In fact it newly rejected none of B's check digits, so B's check let it in, and claim D5 failed.
Tune side, held-out sideThe tune side is everything built from training digits and tune seeds (θ, the antibodies, the tune-seed mimics). The held-out side is the 10,000 test digits and attacks from other seeds, read once after the defence was frozen.
Re-derives from pinned filesEvery data and code file is fixed by its hash, so re-running the tools, on GitHub or in your tab, gives the same numbers to the last digit.
Seal, mutation gateSeal: the claims, then the frozen defence, committed to the public record before the test digits are read. Mutation gate: a tool (witness) that breaks the code in small ways and checks the tests catch every break.

How it works

  1. The floor. A message is 64 bytes of ink, an Ed25519 signature and a key. The key must be on the roster and the signature must verify over the raw bytes before anything is parsed.
  2. The settle. The node settles the image. If the settled state is within reach of nothing it knows, its fit is zero, and it is turned away.
  3. Antibodies. Patterns grown from attacks one node saw. If they hold at least as much fit at the settled state as the node's own patterns, the input is turned away.
  4. Sharing them. Node A signs its antibodies; node B checks the signature first, then makes sure they would not turn away its own genuine digits, and only then adopts them.

Blueprint

    Adoption

    For a business

    A second wall behind signatures, for inputs a stolen key could sign. Random and inverted junk is stopped almost entirely; inputs that look like real ones are not. Know which you face.

    For engineering

    Verify before parse; then a structural check that costs a settle; then shared antibodies adopted only after a local check. Every number re-derives from pinned files.

    For risk and procurement

    The limits are on the page: this does not stop genuine-looking inputs from a stolen key, physical tampering, or bad firmware.

    A pilot, step by step

    1. Pick one input channel where signed inputs arrive and junk or forgeries would cost you.
    2. Write down the bars before anything is built, and seal them: how many real inputs may be turned away, and which attacks must be stopped.
    3. Collect your past real inputs and the attacks you have seen; tune on those only.
    4. Freeze it, then judge it once on held-out inputs and attacks. The fee is due only if it beat your current way.
    5. Run it beside your current checks in monitor mode, rejecting nothing, before it is allowed to turn anything away.

    What it runs on: Node.js 20 or a current browser. No GPU, no cloud service, no model download.

    White paper: a structural wall behind the signature

    The question. Can the settle itself tell a real input from an attack, when the attacker has a valid key?

    The method. Rung 4's node defends itself. Four attack families, 300 each, every one validly signed: scrambled digits, random noise, inverted digits, and an adaptive attacker that hill-climbs the node's own fit for 300 queries. Antibodies grown on node A from tune-seed mimics, shared to B over the signed mesh. The defence was frozen by hash, then judged once on the 10,000 test digits and held-out-seed attacks.

    The results, from the record:

      The limits, plainly:

      • Most of the scrambled digits (about two in three) settle into a real digit's well; at the settled state they are indistinguishable from real digits, and the wall lets them through.
      • The adaptive attacker was stopped by zero fit, not by the antibodies: the settled fit is flat inside a well, so a climb has no gradient. A different attacker could do better.
      • The "harmful" antibody share harmed nothing, so B's gate let it in: the claim about it failed because its premise was wrong.
      • The MNIST test digits were read before by Rungs 3 and 4. Not a fabric (Rung 6), not on a chip (Rung 7).
